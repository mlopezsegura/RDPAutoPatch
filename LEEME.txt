RDPAutoPatch - mantiene el Escritorio remoto parcheado (varias sesiones, tambien del mismo usuario)

Carpeta autocontenida: para llevarlo a otro equipo basta con copiar esta carpeta entera.

Instalar.bat         Instala o actualiza, retira el RDP Wrapper clasico, crea la tarea y comprueba
                     (pide administrador). Vuelve a ejecutarlo si cambias algun archivo de aqui
                     o si TermWrap quedo descartado y quieres reintentarlo ya.
Estado.bat           Muestra el estado sin cambiar nada.
Comprobar_ahora.bat  Fuerza una comprobacion/correccion ahora (pide administrador).
Desinstalar.bat      Quita la tarea, deja el termsrv.dll original de Windows y borra la instalacion.
RDPAutoPatch.ps1     El programa.
TermWrap.dll         Parche dinamico de termsrv.dll.
Zydis.dll            Desensamblador que usa TermWrap.dll.
termwrap\            Codigo de TermWrap.dll: parches sobre llccd/TermWrap v0.7 (MIT) y build.ps1
                     para compilarla (necesita git y Visual Studio Build Tools 2022 con C++).
                     No hace falta copiarla a otros equipos.
osms-extension.json  Extension de OpenStreamMS: se instala desde el panel (Extensiones) con el
osms\                enlace de este repositorio o desde el catalogo oficial. Los scripts de osms\
                     llaman a RDPAutoPatch.ps1 -Install / -Uninstall; si hay sesiones remotas
                     conectadas, el cambio queda pendiente y se pide reiniciar Windows.

Instalado en: C:\Program Files\RDPAutoPatch (la tarea usa esa copia, no esta carpeta).
Registro:     C:\Program Files\RDPAutoPatch\autopatch.log
Eventos:      Visor de eventos > Aplicacion, origen RDPAutoPatch (solo cuando cambia el resultado)
              1000 OK | 1001 Pospuesto | 1002 Degradado (una sola sesion) | 1003 Error | 1004 Interferencia
              Origen TermWrap, al arrancar el servicio: 100 parche de varias sesiones aplicado,
              101 no aplicado (con el detalle de cada parche: ok, partial, failed o missing)

Comportamiento:
- Si TermWrap falla, se reintenta pasadas 24 h; tras 3 fallos se descarta hasta que Windows
  Update cambie termsrv.dll o se vuelva a ejecutar Instalar.bat.
- Si el servicio se cae 2 o mas veces en una hora con TermWrap, cuenta como fallo.
- Si TermWrap se carga pero no encuentra donde aplicar el parche de varias sesiones (evento
  101), tambien cuenta como fallo: el servicio funcionaria, pero con una sola sesion.
- Si hay sesiones remotas abiertas, el cambio se pospone y se aplica en cuanto un usuario
  cierra o desconecta su sesion y ya no queda ninguna conectada.

No instales ni ejecutes el RDP Wrapper clasico (autoupdate.bat, RDPWInst, RDPConf): cambia el
servicio por su cuenta y hace que se pierda el modo de varias sesiones.
